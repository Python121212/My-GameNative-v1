## 読み取り専用の観測

`tools/optimization-observer/collect.py` は、動作中の GameNative に対し `pidof`、`dumpsys cpuinfo`・`meminfo`・`thermalservice`・`battery`・`gfxinfo` を読み取って JSON に保存する。アプリやゲームの起動・停止、インストール、データ消去、設定変更、カウンターリセットは行わない。端末とゲームを手動で準備し、同一の場面で使用する。

```sh
adb devices                      # 対象端末を自分で確認
# GameNative と対象の場面を手動で起動してから
python3 tools/optimization-observer/collect.py \
  --serial '端末のシリアル' --output ./観測結果-基準-1 \
  --samples 4 --interval 10
```

保存先は**存在しない新しいディレクトリ**を指定する。初期状態でプロセスが見つからない場合は開始しない。各サンプルの前後に PID を確認し、変化や消失があれば中断して不完全とする。別プロセスで動く Wine やゲームなどは、この PID 判定だけでは監視できない。途中のコマンド失敗も不完全として記録する。取得成功コードでも端末の権限や実装によって空欄・未対応の場合があるため、必ず中身を確認する。各コマンドの所要時間も記録されるので、重い観測が実行に影響した可能性を評価する。

出力はローカルの `observations.json`。ディレクトリとファイルにはそれぞれ 0700／0600 を指定し、シリアルは明示的に保存せず、コマンド出力中の同じ文字列は置換する。ただしプロセス名、パッケージ名や端末情報などの個人情報が残る可能性がある。Git に入れたり共有したりする前に必ず内容を確認する。端末の情報を安全に保管し、シリアルをチャットに貼らない。出力を自動的にアップロードしない。

### 各指標の意味と限界

- `cpuinfo` は OS の CPU 統計のスナップショットで、他プロセスや測定窓を含む。GameNative の各プロセスとゲームを特定した上で解釈する。GPU 使用率ではない。
- `meminfo` の PSS などはプロセスのメモリ指標で、GPU／共有メモリの実使用量や転送帯域ではない。別プロセス・ドライバーの割り当てはこれだけで把握できない。
- `thermalservice` は端末が報告する種類・状態、`battery` の温度はバッテリー温度であり、CPU や GPU の温度と同一ではない。温度・電力の取得や単位は端末ごとに確認する。取得できない場合は未取得とする。
- `gfxinfo` は収集前からのアプリ UI の累積情報を含み得る。外部描画・ゲーム画面や Vulkan のフレームを代表するとは限らず、**これからゲーム FPS を算出しない**。ゲーム側のフレーム時間／FPS 計測を別途用意する。
- このツールは測定そのものの CPU 負荷や待ちを生じる。実行間隔は各取得処理の開始時刻間の最小値で、処理が長い場合は予定より広がる。測定オン／オフで影響を確かめ、4サンプルを4回の独立したベンチマーク実行と混同しない。

## 次の比較手順

1. APK のハッシュ、コミット、端末・GPU・Android／Wine／変換器、ゲームと場面、解像度、電源・冷却条件を記録し、同じ場面を再現できることを確認する。既存の APK・ゲームデータを維持する。
2. ウォームアップ後に基準を測定し、FPS・フレーム時間は対象ゲーム側の手段で別途記録する。同一条件で4回の独立試行を行い、それぞれ温度や負荷、描画・起動の正確性と失敗を残す。
3. 例えば観測で CPU 側の処理が支配的なら該当経路を調べ、GPU／表示待ちが支配的ならその経路を調べる。候補を一つ変更する前に、対象経路と仮説、検証可能な指標・回帰条件を記す。`dumpsys` 単独では GPU 待ちの確定はできない。
4. 正確性・起動・描画を検査し、変更前後を同一条件で各4回比較する。温度・電力・描画が不明なら改善したと断定しない。必要に応じて [比較記録ひな形](最適化比較記録-ひな形.md) を使う。
5. FEX キャッシュ有効時の Linux 側の出力不一致は未解決。キャッシュ命令の正しい実行を確認する前に、速度比較の成功と扱わない。Android 用 FEXCore／WOWBox64 は別に検証する。CPU 比較で改善と正確性を確認した場合のみ SuperTuxKart に進む。

エミュレーターでの動作確認、ARM Linux の実験、Mali の静的解析はいずれも Pixel 9a 実機の FPS・温度・性能の代わりにならない。`malioc` が利用可能になった際は [Mali 解析手順](mali-shader-analysis-ja.md) を使用する。
