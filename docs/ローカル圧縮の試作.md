# ローカル圧縮・部分読み込みの試作

## 今回作ったもの

試験 APK の「設定 → デバッグ → 圧縮と部分読み込みの試験」から、自動生成した約700 KBのデータをアプリの一時領域に作り、可逆圧縮・50箇所の部分読み込み・ブロック境界の照合ができる。結果には元サイズ、圧縮サイズ、所要時間を表示する。終了時は試験専用の新規ディレクトリだけを削除する。ゲーム・セーブの読み取り、送信、変更はしない。結果は人工データの値で、ゲームの圧縮率・ロード時間・FPS ではない。

`ChunkedAssetFile` は独自の実験形式であり、EROFS／SquashFS／Unreal `.pak` ではない。256 KiB ごとに zlib 圧縮し、インデックスで部分読み込みを行い、直近2ブロックをメモリ上に保持する。ブロックごとに展開長と CRC32 を確認する。CRC32 は偶発的な破損検出用であり、改ざん防止・認証ではない。出力先の既存ファイルは上書きせず、失敗時はその操作で新規作成した出力のみ削除する。入力のサイズが変わる変更は失敗として扱うが、同一サイズの同時変更を確実に検出できないため、入力を静止させる仕組みが必要。ストレージ不足・中断・破損時に実ゲームを守る仕組みは未完成。

## 重要な制限

- **ゲームの圧縮や起動には未接続。実ゲームの容量は減らない。** ファイル選択や実ゲームの圧縮ボタンは設けていない。
- 透過的なファイルアクセス、Wine の `mmap`、ディレクトリ、ファイルメタデータ・ロック・同時アクセス・ゲーム更新・セーブ分離は未実装。独自形式は単一ファイルをアプリ内の API から読むだけ。
- EROFS／SquashFS のカーネル機能を利用したマウントや root なし Android アプリでの実行は未検証。Pixel 9a のカーネル対応や制限も未確認。
- コンテナやゲームデータの移動・削除は行わない。Steam の整合性、署名、暗号化、オンライン保護を回避しない。ゲームを取得・アップロード・配布しない。
- 256 GiB までの単一ファイル、1回の読み込みは4 MiBまでという試作用制約がある。書き込みは読み取り専用キャッシュと別に扱う設計も未実装。

## 検証と次の段階

Android エミュレーターの試験では自動生成データの読み込み、ブロック境界、空データ、既存出力への上書き拒否、範囲外拒否、CRC不一致、途中欠損を検査する。エミュレーター上の成功は Pixel 9a の性能や実ゲームの正しさを示さない。

次に、無料のテストデータで EROFS・SquashFS の容量やランダム読み込みを別途比較し、root なし Android からファイルを透過的に見せる手段を検証する。続いて Wine の `read` / `pread` / `mmap`、属性、パス、同時操作と書き込み分離を検証し、実ゲーム利用の前に更新・中断・容量不足時の安全な復元を実装する。Escape the Backrooms のファイルを利用者自身が調べる場合も、許可された範囲でローカルのみで行い、ゲームファイルを第三者に渡さない。実ゲームや既存データへの適用は、これらの検証後に改めて判断する。
