# Freedoom の描画改善候補：4比較

[実行 43552556137](https://github.com/Python121212/My-GameNative-v1/actions/runs/43552556137)。以前の SDL 計測で DXVK は Present、WineD3D は Present と texture Unlock の CPU 側経過時間が大きかったため、その周辺の設定を候補として比較した。設定の切り替え試験であり DXVK／WineD3D のコード変更ではない。4比較は並列の独立した runner であり、前の比較を改良して次に進む4回の連続した最適化ではない。WineD3D の後半2比較は同一候補の独立再検証である。

各 runner 上で既定設定・候補を交互に、順序を2回ごとに反転させ、ウォームアップ後それぞれ4回実行。DLL 種類および候補設定の読み込みをログで確認。Chocolate Doom 3.1.1＋Freedoom 0.13.0 の DEMO1、x86-64 Linux Wine、ソフトウェア Vulkan lavapipe／OpenGL llvmpipe。固定フレーム120の読み戻しを含む timedemo の値であり、各 runner 間の絶対 FPS を直接比較しない。

DXVK の直接マッピング設定は D3D9 の対象バッファの扱いを変更するが、SDL のテクスチャ経路に効くとは限らない。今回の差は小さく改善を確認できない。フレーム待ち数の候補も改善を示さなかった。WineD3D の候補は2環境とも平均が高かったが差は小さく、比較4の最終試行は基準より低い。少数試行かつ共有 runner のため安定した効果とは断定できない。試験は4回の順次最適化ではなく、アプリに改善を組み込めたわけでもない。候補はいずれも既定値に採用していない。

全32計測は 2664 gametics で完走し、固定フレーム120の RGB は全条件で完全一致（SHA256 `2342af2ac6da4d8b3048b9268e4ec6a58c73c4215076824656640d4c8c124cbe`）。検査は1フレームで、全フレームの正確性を保証しない。FPS 以外のフレーム時間分布、消費電力、発熱、実転送量は未測定。Android 実機・GPU・GameNative の性能には一般化できない。計測用設定は一時 prefix に限定し、既存 APK とゲームデータは変更していない。詳細ログ・PNG は Actions 成果物に14日間保存。
