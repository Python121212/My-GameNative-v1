# 圧縮ファイルのゲーム接続と仮想メモリの調査

## 今回の状態

**圧縮ファイルを Escape the Backrooms や Wine に透過接続する機能は未完成。システムのスワップ／ZRAM の拡張・設定変更も行っていない。** 実ゲーム、Steam、Pixel 9a は試験していない。試験 APK で利用できるのは人工データを使う実験とメモリ状態表示であり、ゲーム容量や実効メモリが増えたとは言えない。既存ゲーム・セーブ・APK は変更しない。

## Android の圧縮 FD 実験

`CompressedAssetProxy` は独自の `ChunkedAssetFile` を Android の `StorageManager.openProxyFileDescriptor` により読み取り専用・シーク可能なファイル記述子として公開する。root は要求せず、圧縮ブロックごとのサイズ・CRC を検査する。これは EROFS/SquashFS のマウントではない。人工データに限定し、ゲームのパス・保存・更新には組み込まない。

[エミュレーター試験 43592227855](https://github.com/Python121212/My-GameNative-v1/actions/runs/43592227855) は Android 35 x86_64 + ARM bridge で、アプリプロセス内の native `pread`、ブロック境界、末尾、書き込み拒否、読み取り専用 `mmap` とキャッシュ解放後の読み込みを確認した。実ゲーム／Wine・他の端末での対応は示さない。

追加した [試験 43593198035](https://github.com/Python121212/My-GameNative-v1/actions/runs/43593198035) は、同一アプリの子プロセスから `/proc/<親PID>/fd/<FD>` を通して人工ファイルを読もうとしたが終了コード1で失敗した。[再試験 43593616939](https://github.com/Python121212/My-GameNative-v1/actions/runs/43593616939) では `Permission denied` を確認し、親が `/proc` を通して開いた FD を子の標準入力に渡す代替試験も利用不可だった。詳細な権限拒否の原因は未確定。Android の子プロセスから通常のファイルとして開けると仮定してはいけない。再試験では子プロセス経路の失敗をログに明記し、アプリ内の native `pread`・`mmap` 等の9件と起動・描画を再検査した。子プロセスの失敗を接続成功とは扱わない。

今後は FD の安全な受け渡し、Wine のパス解決、`read` / `pread` / `mmap`、寿命、複数ファイル・同時アクセス、ディレクトリ・属性・ロック、書き込みの分離を調査する。ゲーム更新・中断・容量不足・破損時に既存データを守る方法が必要。権利や Steam の整合性・保護機構を回避しない。AI・ゲームデータの送信・再配布は行わない。

## メモリ・スワップ

- 「設定 → デバッグ → メモリ・スワップの状態」で Android が報告する空き／合計メモリと、読める場合に `/proc/meminfo` の SwapTotal・SwapFree を表示する。読めない場合は取得不可。スワップ合計は ZRAM に限らない。
- メモリ不足などで `MainActivity.onTrimMemory` が UI 非表示以上の通知を受けた際、開いている圧縮試作の再取得可能な最大2ブロックのキャッシュを解放する。後で必要なブロックを再展開する。これはアプリ内のメモリ管理であり、システムの swap/ZRAM の制御ではない。Android が常に通知する保証はない。
- 通常のアプリではスワップ設定に必要な権限やシステム設定への書き込みがないことが多い。実際の Pixel 9a で権限やメモリ使用・発熱は未測定。勝手に root 化・swapon・swapoff・スワップファイル作成・システム設定変更は行わない。
- キャッシュ解放の性能やメモリ削減、実ゲームの安定性の向上は未測定。Android の Low Memory Killer が作動しない保証にもならない。
