# 命令変換の比較：準備と未実施事項

## 目的と現在の状態

Windows x86-64 の CPU ベンチマークを、同じ ARM 環境の GameNative 上で FEXCore と Box64 系の両方から実行し、各条件4回の平均を比較する。変更前後も同条件で4回ずつ測る。改善・正確性・起動を確認できた場合だけ SuperTuxKart に進む。現時点で計測結果はなく、速度や温度の改善は確認できていない。

2026-11-13 の調査では、作業環境は x86_64 で、Android 端末・adb・ARM 実行環境は利用できなかった。Android 35 x86_64 の ARM 変換エミュレーターでは Android アプリの起動・描画は確認できるが、Windows x86-64 → ARM → x86_64 の二重変換となるため Pixel 9a の速度測定には使えない。GameNative の実際の FEXCore／Box64 パック、Wine、Windows 実行ファイルを含む実験環境もまだ用意していない。ARM エミュレーターや ARM ホストでの検証ができても、その結果を Pixel 9a の実測と混同しない。

## FEX キャッシュの事前調査

- `FexCodeMaps.packSupportsCodeCaches` は、FEXCore パックの `system32/FEXOfflineCompiler64.exe` を対応判定に使用する。
- 2026-11-13 に `app/src/main/assets/fexcore/` 内の8つの tzst の中身を調べたところ、いずれにも同名のコンパイラーは含まれていなかった。対応可否の判定は同梱ソースに基づくものであり、ほかの方法でのキャッシュ利用の可否を断定するものではない。
- `manifest.json` に記載された `2611-gn-6` は、[ARM 環境確認](https://github.com/Python121212/My-GameNative-v1/actions/runs/43416334467)でダウンロードでき、パック内に `FEXOfflineCompiler64.exe` があることを確認した。ただし動作は未確認。外部の配信やコードマップのアップロードが関係するため、通信先とプライバシー設定を確認する。
- コードマップの生成、サーバーからのキャッシュ取得、実際の読み込みは別々の段階である。各段階のログ・ファイル・対応バージョンを記録し、ファイルの存在だけでキャッシュ命中と判断しない。読み込みを直接確認できなければ「未確認」と記録する。

## 比較手順

1. 無料の CPU ベンチマーク候補として [CoreMark](https://github.com/eembc/coremark) のライセンス・実行ルールを確認し、同じ Windows x86-64 実行ファイルと入力を両変換器で使用する。計算結果の正しさを比較し、異常終了や出力不一致は速度から除外せず失敗として報告する。まだバイナリは作成していない。
2. 端末・OS・GameNative・Wine・変換器のバージョン、設定、電源、温度、キャッシュ状態を記録。キャッシュ有効と無効は各々別条件とし、既存データを消さず、専用のテスト環境で比較する。
3. ウォームアップを測定回数と別にし、FEX／Box64 を交互に各4回実行。各回の時間・スコア・成功／失敗・温度を保存し、4回とも成功した条件だけ算術平均と各回のばらつきを示す。順番を記録し、熱による偏りに注意する。
4. 変更を一つだけ入れ、同じ条件で再度4回ずつ測定する。スコアや時間の方向を明示し、性能だけでなく正確性、安定性と発熱も比較する。4回だけでは統計的確実性は限定される。
5. CPU 比較で改善が確認された場合のみ、無料の [SuperTuxKart](https://github.com/supertuxkart/stk-code) の Windows 版と固定シーンの実行可否を調べ、描画・ゲーム動作を検証してから同様に各4回ずつ測る。固定シーンが再現できなければ比較結果とはしない。FPS とフレーム時間、温度を記録する。

Pixel 9a や ARM 実機が利用できない場合、性能と発熱の実機評価は保留する。実行可能な試験環境を構築し、結果を取得するまで最適化を採用したと判断しない。

## ARM 実行環境の追加調査

[GitHub Actions 実行 43416334467](https://github.com/Python121212/My-GameNative-v1/actions/runs/43416334467) で ARM64 の Linux ホストが利用可能と確認した。これは Android／Pixel 9a ではなく、Wine・GameNative・FEXCore／Box64 の実行環境は未構築である。ホスト確認とパック内容確認は `tools/translation-benchmark/probe-arm-runner.sh` で再実行可能。モックで正常系と x86 ホストの拒否を検査した。

[実行 43416334382](https://github.com/Python121212/My-GameNative-v1/actions/runs/43416334382) では、既存の Android エミュレーターの APK ビルド・描画・起動回帰テストが成功した。CPU の変換性能計測ではない。CoreMark のライセンスには利用条件があり、Windows 向けビルドや結果の取り扱いを確認してから使用する。

## Windows ベンチマーク実行環境の試験構築

無料の 7-Zip 26.06 Extra から Windows x86-64 版 `7za.exe` を取得する手順を追加した。公式リリースの SHA-256 を検証し、x86-64 PE であることを確認する。[実行 43423704328](https://github.com/Python121212/My-GameNative-v1/actions/runs/43423704328) では x86_64 Linux 上の Wine でベンチマークが正常終了した。これは性能比較ではない。

[実行 43431823501](https://github.com/Python121212/My-GameNative-v1/actions/runs/43431823501) では、ARM64 Linux ホスト上に Linux 版 FEX と Box64 0.4.4、x86-64 Wine 11.0 を用意し、同一の 7-Zip Windows 版が両方で正常終了した。Box64 の Wine 初期化がタイムアウトしたため、動作確認では FEX で初期化した Wine 設定のコピーを使用した。独立した初期化は未解決であり、これは公平な比較ではない。外部の Wine コンテナイメージはダイジェストで固定し、一時 runner にのみ展開する。

この環境の FEX／Box64 は Linux 用であり、GameNative の Android 用 FEXCore／WOWBox64 DLL とは異なる。動作確認結果を Pixel 9a や GameNative の実測として使わない。FEXCore キャッシュの読み込み確認、各条件4回の比較、改善と再測定は未実施。SuperTuxKart も未実施。GitHub Actions の成果物は保存期間が14日であり、既存の公開 APK は変更していない。
