# GameNative の FEXCore 検査

## 結論

GameNative 側のコードマップ判定・解析とパック構造は検査できたが、**Android の FEXCore DLL による Windows プログラム実行、キャッシュの実読込、ゲームの正常動作は未検証**。Linux ARM 版 FEX で発生したキャッシュ有効時の出力欠落・SIGSEGV が Android でも発生するか、原因が共通かは判断できない。問題がないとも断定できない。

## 実施した検査

- [Actions 43567356695](https://github.com/Python121212/My-GameNative-v1/actions/runs/43567356695)：同梱8種・公式配布2種のパックを静的検査、PE ヘッダー・各 SHA-256 を記録。APK ビルド、FexCodeMapsTest / FexImagesTest、Android 35 x86_64 + ARM bridge での基本描画・起動・60秒生存、および Android 上のコードマップ解析・パック判定のテストに成功。Android の新テストは DLL を実行しない。
- コードマップの32-bit、符号なし相当オフセット、未知の予約レコード、終端なしレコード、コンパイラーと同名のディレクトリを追加検査。実機由来のマップ fixture も既存の単体テストで確認。
- 同梱 2507、2508、2511、2512、2601、2603、2604、2605 はいずれも両 DLL を含み、`FEXOfflineCompiler64.exe` は含まない。既定値 `2610-gn-5` は同梱パックではなく外部配布で、検査したパックにも同 compiler はない。`2611-gn-6` の外部パックには同 compiler がある。
- 取得した外部パックの SHA-256：`2610-gn-5` = `751868eb8f6db99ef09146a946c45c981fc11d65eeca58337d5a22e3ef176a5e`、`2611-gn-6` = `7455d152192f08927871d459f2dc654a9d40f9690205aac6fb6f08c753bfa2db`。これは取得物の識別用であり、配布元が提供する期待値との照合や署名検証ではない。詳細は Actions の成果物を参照（保存期間14日）。

## 実装から分かること

- ARM64EC Wine で FEXCore を選択すると、起動時に `HODLL=libwow64fex.dll` が設定される。ARM64EC 以外は Box64 経路。DLL の存在やヘッダーの正しさだけでは正常なロード・命令変換を証明できない。
- `fexCodeCacheEnabled` の既定はオン。ただしアプリによるコードマップ収集は FEXCore の選択、設定、対象パックの `system32/FEXOfflineCompiler64.exe` の存在などで制限される。起動環境変数 `FEX_ENABLECODECACHINGWIP` は判定に応じて設定または削除される。
- この設定をオフにした場合に、FEXCore 自体が既存のキャッシュを絶対に読み込まないかは未検証。ファイルの存在チェックはコンパイラーの実行可能性やキャッシュの正しさを証明しない。
- Android エミュレーターの起動検査はゲーム起動ではない。また、x86_64 + ARM bridge の結果を Pixel 9a の性能・発熱とみなすことはできない。

## 次に必要な実行検証

1. ゲームデータを消さず、隔離した新規テスト用コンテナと Wine prefix を用意。実行 APK、Wine、FEXCore パック、DLL のハッシュと環境を記録する。
2. ARM64EC Wine + FEXCore で、出力と終了コードが決まった Windows x86-64 の小さなテストを実行し、ロードされた DLL と結果を確認。通常実行とキャッシュ関連設定の差を別々に検査する。
3. `2611-gn-6` など対応パックを使い、コードマップとオフライン生成キャッシュの生成・対象一致・実ロードをログ等で証明し、同じプログラムで出力・終了コードを比較する。ファイル生成や mmap だけではキャッシュされた命令の実行を証明できない。
4. 正常性を確認してから無料 CPU ベンチマークで FEXCore と WOWBox64 をそれぞれ4回測定し、改善後に同条件で再測定する。Pixel 9a 実機での温度・FPS は別途測定する。

テスト用環境の Wine / パック導入と Windows プログラムの実行は今回未実施。既存の Linux FEX の障害については `命令変換ベンチマーク計画.md` を参照。
