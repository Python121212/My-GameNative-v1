# GameNative 作業記録

## ソースの導入

- `utkarshdalal/GameNative` の `master` のソースを、上流の Git 履歴なしで取り込みました。サブモジュールも指定されたコミットの内容を取得しました。

## APK とビルド

- CLI 向けビルド準備の手順と診断スクリプト、GitHub Actions の debug APK ビルドを追加しました。
- modern debug APK を GitHub Releases で公開しました。対象は Android 10 以降、arm64 です。debug 署名版であり、製品配布用の署名版ではありません。
- [計測後のリリース](https://github.com/Python121212/My-GameNative-v1/releases/tag/debug-43390285232)
- 同一 GitHub Actions ランナーでのクリーンビルド4回の所要時間は、順に303秒、20秒、17秒、16秒でした。2回目以降はキャッシュを利用しています。SDK の準備とアップロード時間は含みません。
- Kotlin コンパイルのメモリ不足で一度失敗し、設定を変更した後の再実行は成功しました。

## 描画の確認

- Pixel 9a に向けた実機検証手順と、OpenGL ES の基本描画テストを追加しました。
- ARM64 ライブラリを ARM 変換機能で読み込む Android エミュレーターと、基本描画テストを GitHub Actions で実行し成功しました。
- エミュレーターは Pixel 9a の GPU とドライバーを再現しないため、Pixel 9a やゲームの描画成功は確認できていません。

## Mali Offline Compiler

- Mali-G715 向けシェーダー解析スクリプトと、エミュレーターテストを組み合わせるワークフローを追加しました。
- 成功した解析結果を、シェーダー、GPU、ツールなどに基づいてキャッシュする仕組みを追加し、モックを使って検証しました。
- `malioc` と `glslangValidator` を備えたセルフホストランナーが必要です。実際の Mali シェーダー解析やキャッシュによる高速化は、この記録作成時点では確認できていません。静的解析は実機での動作を保証しません。

- GitHub Actions で debug APK のビルド、Android エミュレーターでの ARM ライブラリ読み込み・基本描画・フィルターの検査を整備した。公開済みの [debug APK](https://github.com/Python121212/My-GameNative-v1/releases/tag/debug-43390285232) はその後の変更を含まない。
- OpenGL のフィルター設定の重複送信と、条件に合う場合の中間バッファを減らした。コード上の削減であり、FPS や発熱の改善は未測定。通常の Vulkan 経路への効果は示していない。
- Mali-G715 の静的解析と結果キャッシュの手順を追加し、モックで検査した。実際の Mali Offline Compiler による解析は未実施。

### 発生した問題と対応

- ビルド時に Kotlin のメモリ不足が起きたため設定を変更し、その後の APK ビルドは成功した。
- 描画の変更後、エミュレーターで APK 起動数秒後に GPU 情報取得のネイティブクラッシュが発生した。GPU 列挙失敗時の処理を安全化し、独立した JNI ライブラリを使用するよう修正した。[修正後の実行](https://github.com/Python121212/My-GameNative-v1/actions/runs/43413964189) では5件のテスト、起動、前面表示、10秒間の生存を確認した。長時間動作や実機での安定性は未確認。
- ARM Linux の Wine 実験では proot 経由で変換器がクラッシュし、直接の rootfs・ライブラリパス指定で回避した。Box64 の新規 Wine 環境の初期化は当初タイムアウトしたが、設定を調整した[実行](https://github.com/Python121212/My-GameNative-v1/actions/runs/43434043199)で FEX の設定をコピーせず Windows 版 7-Zip の実行に成功した。タイムアウトの根本原因は未特定。
- Linux 版 FEX の配布パッケージには必要なオフラインコンパイラーがなかったため、同じ固定ソースからビルドして試験した。キャッシュの生成・ファイルの mmap は確認したが、キャッシュ有効時の最小プログラムは期待した出力をせず、ゼロ長 write を行った。無効時は正常で、内蔵照合はクラッシュした。ブロック結合の無効化でも解消せず、原因・修正は未確定。[詳細と試験結果](命令変換ベンチマーク計画.md)を参照。ファイルの存在や読み込みだけでは正しい実行を示さない。

### 現在の状態と次の作業

- [PR #12](https://github.com/Python121212/My-GameNative-v1/pull/12) は調査中のドラフトで、FEX キャッシュ検査は失敗したまま。今回の調査記録と変更は main に未反映であり、正常動作を確認せずにマージしない。
- ARM Linux の FEX／Box64 は GameNative の Android 用 FEXCore／WOWBox64 とは別物。Android 用キャッシュの実読み込み、Pixel 9a 実機での動作・FPS・温度は未確認。x86 ホストの ARM 変換エミュレーターの結果や Mali の静的解析を実機性能とみなさない。
- 次の最適化の前に、FEX キャッシュの正確性を引き続き調査し、無料 CPU ベンチマークを同条件で FEX／Box64 各4回測る。結果の正しさと各回の値を記録し、変更後に同条件で再測定する。改善を確認できた場合に限り SuperTuxKart に進む。これらの比較はまだ行っていない。
- ゲームデータと既存 APK を保持し、起動と描画の回帰試験を優先する。発熱と FPS の両方を評価し、実測できないものは未確認と記録する。
