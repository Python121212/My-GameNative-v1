# Pixel 9a での確認と APK の上書き

## データを消さずに確認する

アプリの上書きには Android のパッケージ名、署名（または正当な署名移行）とバージョンなどの整合が必要。署名が違う APK は既存データを保持したまま上書きできない。今までの GitHub Actions 試験版は runner 上で生成される debug キーを使っており、別の実行で同じキーとは保証されず、過去のキーはこのリポジトリに保存されていない。今回も上書きできる保証はない。公式版・別配布元の署名キーを推測・再作成して互換にすることもできない。

現在の GameNative の**入手元、バージョン、インストールした試験版の URL** が分かれば確認する。PC があり USB デバッグに同意する場合だけ、次の読み取り専用コマンドでバージョン等を確認する（端末のシリアル等を共有する前に確認）：

```sh
adb shell dumpsys package app.gamenative | grep -E 'versionCode=|versionName=|signatures=|SigningInfo'
```

署名の実際の証明書 SHA-256 の取得は Android バージョンや表示ツールに依存する。比較可能な証明書の公開フィンガープリントだけを扱い、秘密鍵・パスワードはチャットで送らない。署名が一致しない／インストールが拒否されたら、**アンインストール、アプリデータの消去、強制再署名を行わない**。既存ゲームとセーブのバックアップ方法を確認してから、既存署名の管理者が同じ署名鍵でビルドする必要がある。今回の APK は上書き対応済みとは言えない。

## 実機で行ってほしいこと（安全な範囲）

1. まずインストール済みの GameNative の入手元・バージョンと、セーブのバックアップ状況を確認する。まだ旧 APK を削除しない。
2. 上書き可能な試験版が入った場合のみ、設定 → デバッグ → 測定用ソフトから AIO Graphics Test をブラウザで入手し、「測定用 EXE を選んで起動」で EXE を選ぶ。独立したテスト用コンテナで起動する設計だが、Pixel 9a・GameNative 上の実動作は未確認。EXE 選択時のコピーと初回コンテナ準備のため、追加容量と通信が必要。
3. 起動できたら DX11 画面の表示・操作と、エラー文を確認。無理に長時間回さず、高温・強い発熱・不安定動作時は中止する。実行できたか、画面表示の状態、アプリと Android のバージョンを記録する。Steam ID・認証情報・他人の名前・ゲームファイルは送らない。
4. CPU の 7-Zip は選択するファイルがインストーラーであり、選択後にコンテナ内へのインストール操作が必要。インストール後に File Manager を開いて Tools → Benchmark を選ぶ。起動経路は実機未検証。失敗したらその時点で停止し、エラーの文面だけを共有する。

自動30回の連続測定は実装・実行していない。実機に遠隔接続する手段はこの会話にない。まず起動と描画の正確性、安全な温度・中止方法が確認できてから、対象（CPU／DX11）、回数、休憩や結果保存について合意する。実機なしのエミュレーター結果を Pixel 9a の性能として扱わない。
