# リリース署名の確認状況

## 現在の状態

ユーザーの希望は、試験版・安定版の両方をリリース署名で作成すること。ただし [署名設定の有無の確認 43651361895](https://github.com/Python121212/My-GameNative-v1/actions/runs/43651361895) では、このリポジトリの Actions から参照される production 署名の設定4項目のうち少なくとも1項目が未提供であり、検査が失敗した。どの項目が不足しているか、秘密鍵の有無や中身は表示・取得していない。秘密設定一覧の確認権限もなかった。**リリース署名付きの試験版・安定版の作成と公開は未実施。**

同ワークフローの現在版は設定が不足していても警告のみで終了する。これは他の変更を妨げないためであり、署名可能であることを意味しない。署名や公開は一切実行しない。4項目が存在した場合も、実際に正しい署名ができることやインストール済みアプリと一致することは別途確認が必要。

## 上書きに必要なこと

Android はアプリの署名などを確認する。任意の新しいリリース鍵で署名しても、現在インストールされたアプリと同じ署名または正式な署名移行がなければ上書きできない。既存の debug 署名の試験版と公式版は、同じ鍵とは限らない。バージョンコードも上書き条件に関係する。既存アプリの入手元とバージョン、公開証明書の SHA-256 を確認する必要がある。公開用 APK の署名検証と、既存インストールからの上書き・データ保持の確認を行うまでは「上書き可能」と案内しない。

署名鍵の管理者は、対応する既存のリリース署名鍵が利用可能かを確認し、リポジトリの GitHub Actions の保護された署名設定を適切に整備する。**秘密鍵、キーストア、パスワードをチャットやリポジトリに送信・保存しない。** 別の鍵を自動生成して既存版と互換と偽らない。権限や安全な鍵管理の準備が整うまで、インストール済みアプリのアンインストールやデータ消去をしない。

## 次の検証

- 試験版と安定版それぞれの対象コミット・バージョンコード・パッケージ名を確認。署名証明書が対象ユーザーの既存版に適合するか検査する。
- リリース署名でビルド後、署名と APK ハッシュを検証し、テストした APK と公開物が同一であることを確認する。試験版と安定版は明確に区別する。
- Android エミュレーターで起動・表示・可能な描画試験、既存版からの上書きとデータ保持を確認する。署名鍵が異なる実際のアプリや別バージョンへの互換は別検証が必要。
- Pixel 9a、実ゲーム、Steam・マルチプレイ、性能・発熱は別途実機で確認する。基本起動試験だけで安定版の品質を保証しない。
