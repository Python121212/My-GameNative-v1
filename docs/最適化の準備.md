# 最適化の準備と計測

## 最初に

目的（APK ビルド時間、アプリのメモリ、ゲームのフレーム時間、描画など）を一つずつ決め、変更前後に同じ条件で測定します。バックアップは `main` の `backups/GameNative-source-backup.7z`（Git LFS）と作業記録を参照してください。APK やゲームデータはこの手順では削除しません。

```sh
./tools/prepare-optimization.sh
```

これは Git の状態、ホストのメモリ・ディスク空き容量、ツールの有無を表示するだけで、プロセス停止、データ削除、APK 生成はしません。メモリを調べる場合は OS が再利用できるキャッシュも含む `available` に注目してください。環境のプロセスを無差別に終了したり、OS のページキャッシュを消したりする必要はありません。

## メモリのリセット

Android 端末またはエミュレーターを使用する場合、計測前にゲームを正常終了し、セーブされたことを確認してください。次のコマンドは **対象端末の GameNative を強制停止**し、プロセスの一時メモリを解放します。進行中の処理やプレイは中断されます。アプリデータ・ゲーム・ファイル・キャッシュは削除しません。

```sh
adb devices                         # 対象を確認
./tools/prepare-optimization.sh --reset-app '端末のシリアル'
```

`--reset-app` はシリアルを明示しないと実行できません。停止後にアプリを手動で再起動します。OS 全体の RAM を初期化したり、GPU ドライバーや他アプリのメモリをリセットしたりするものではありません。シリアルを外部に公開しないでください。接続された実機がない場合、この操作は実行できません。

開発環境で Gradle のデーモンを停止する場合は、**同じユーザーが使っている他のプロジェクトのデーモンも対象**になることに注意し、作業を終了したうえで `./tools/prepare-optimization.sh --stop-gradle` を実行します。Gradle のダウンロードが必要になる場合があります。これはキャッシュの削除ではなく、デーモンを使っていなければリセットするものはありません。

## 比較条件と記録

- コミット、APK 種別、Android バージョン、端末またはエミュレーターの種類、GPU とドライバー、対象ゲームと設定を記録します。
- メモリは同じ場面・起動後の同じタイミングで `adb -s <シリアル> shell dumpsys meminfo app.gamenative` を取得し、PSS など同じ項目を比較します。取得結果の共有前に個人情報を確認してください。
- 各試行の前に上記のアプリ停止を行い、同じ操作を再現します。少なくとも複数回の測定値と中央値、ばらつき、クラッシュや画面の乱れを記録します。
- フレーム時間の計測ではアプリ UI とゲーム描画を区別し、利用する計測手段と対象を明記します。`dumpsys gfxinfo` はゲームの Vulkan／外部描画を完全には表しません。
- ビルドは SDK の準備、コンパイル、APK アップロードを分け、キャッシュあり／なしを混同しません。既存のクリーンビルド4回の記録は `docs/作業記録.md` にありますが、異なるランナー条件との厳密な比較はできません。
- Mali の解析は `docs/mali-shader-analysis-ja.md` に従って実行します。キャッシュ利用時は再解析していないため、新しい性能測定として扱いません。Mali Offline Compiler の結果は GPU 上の実測やゲーム互換性を保証しません。

エミュレーターは Pixel 9a の GPU とドライバーを再現しません。端末固有の描画・性能を評価する場合は、実機か該当機種が利用可能なクラウド実機で確認してください。ビルドや APK の更新は、明示的に実行するまでは行いません。
